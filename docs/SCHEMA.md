# 数据表结构（飞书多维表格）

表名：**私域社群表**　共 21 列。前 19 列由程序写入，最后 2 列留给人。

> 用自建应用 API 写入时，字段类型必须与下表一致；**`群ID` 必须是「文本」**——Discord 的 19 位 ID 超过 `2^53`，存成数字会丢精度。

| # | 字段名 | 类型 | 说明 / 取值 |
|---|---|---|---|
| 1 | 群组唯一键 | 文本 | 建议 `平台-标识`，如 `FB-CS2TradingPalace`、`TG-cs2trading`、`DC-1084023591…` |
| 2 | 平台 | 单选 | `Facebook` / `Telegram` / `Discord` / `Reddit` |
| 3 | 群ID | **文本** | FB 群数字 id、TG `@username`、DC guild id |
| 4 | 群名 | 文本 | 群组显示名 |
| 5 | 群链接 | 文本（URL） | `https://t.me/xxx` / `https://facebook.com/groups/xxx` |
| 6 | 成员数 | 数字 | 采集时的成员/订阅数 |
| 7 | 上次成员数 | 数字 | 上一轮采集值，用于算变化 |
| 8 | 成员数变化 | 数字 | 普通数字列（不要用公式列，公式列批量写入会错位） |
| 9 | 语言 | 文本 | `en` / `ru` / `pt` / `uz` / `da` / `th` … |
| 10 | 群类型 | 单选 | `公开群` / `非公开群` / `频道` / `聊天` / `服务器` |
| 11 | 状态 | 单选 | `已加入` / `待审核` / `需验证-不申请` / `失效` / `已退出` |
| 12 | 加入日期 | 日期 | 写入时用 `YYYY/MM/DD`；读回来是 epoch 毫秒 |
| 13 | 潜水到期 | 日期 | 加入日 + 3 天，即允许发第一帖的最早日期 |
| 14 | 日发帖量 | 数字 | 搜索结果里平台显示的「每天 N 篇帖子」，没有就留空 |
| 15 | 采集来源 | 单选 | `FB搜索` / `TG搜索` / `目录站` / `群内互推` / `Discord API` / `人工` / `其他` |
| 16 | 采集日 | 日期 | 本轮采集日期 |
| 17 | 最后核验 | 日期 | 上一次确认该群仍存活/仍加入的日期 |
| 18 | 失效原因 | 文本 | 如「3 天无新帖」「群已解散」「被移出」 |
| 19 | 是否收费发帖 | 单选 | `是` / `否`（部分 TG 群每条消息收费，如 2 Stars） |
| 20 | 负责人 | 文本 | 人工填写 |
| 21 | 备注 | 文本 | 人工填写 |

## 为什么这几列要这么设计

- **单选列**：选项必须**逐字一致**，拼错会新建一个选项，看板的分组就散了。
- **`成员数变化` / `潜水到期` 用普通列**：飞书公式列是只读的，批量写记录会整体错位。
- **`状态` 是看板「待办」的数据源**：`状态 ≠ 已加入` 的记录会出现在待办区。
- **`加入日期` 决定「今日新增」与 7 天趋势**：写入用 `yyyy/MM/dd`，读取兼容 epoch 毫秒。

## 建表最省事的办法

1. 新建多维表格 → 按上表建 21 列（类型照抄）；
2. 把单选列的选项一次性建好；
3. 把 `base_app_token`、`table_id` 填进 `config.json`；
4. 用 `lib/feishu.ps1` 的 `Add-FsRecords` 先写一条测试记录验证。
